# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a Werewolf AI Party Game where AI bots pretend to be humans and don't know about other AI players. Each bot has personal goals, secret roles, and alliances. The game supports multiple AI models from OpenAI, Anthropic, Google, DeepSeek, and Mistral.

## Development Commands

All commands should be run from the `werewolf-client/` directory:

```bash
# Development
npm run dev          # Start development server on localhost:3000
npm run build        # Build for production
npm run start        # Start production server
npm run lint         # Run ESLint
npm run test         # Run Jest tests

# Firebase (requires Firebase CLI)
firebase deploy --only firestore:indexes    # Deploy Firestore indexes
```

## Architecture

### AI Agent System — the `@hiper2d/ai-agents` library
The agent layer lives in the npm package [`@hiper2d/ai-agents`](https://github.com/hiper2d/ai-agents) (repo: `~/projects/ai-agents`), extracted from this app in Aug 2026. The split:
- **Library owns model facts**: per-provider agents (`ClaudeAgent`, `Gpt5Agent`, `GoogleAgent`, …), `AbstractAgent` (template method with logging, per-instance `maxOutputTokens` / `reasoningEffort` / `thinkingBudgetTokens`), `AgentFactory`, the model catalog (`SupportedAiModels`, `LLM_CONSTANTS` — constant name = version-free picker id in upper snake case), `MODEL_PRICING` + cost accounting, schema-validated asks via `askWithZodSchema()`, thinking extraction. Since 0.2.0 also the **voice agents**: `VoiceAgentFactory` → `speak()` / `transcribe()` for the `openai` (gpt-4o-mini-tts + Whisper) and `google` (Gemini TTS + Transcribe) providers, `VOICE_MODEL_CONSTANTS` / `VOICE_MODEL_PRICING`; agents report `costUSD`, the app's `tts-actions.ts` / `stt-actions.ts` only do auth, tier and billing. Since 0.5.0 also the **images subpath** (`@hiper2d/ai-agents/images`): the Gemini image call, the cast portrait sheet (grid layout, sheet prompt, divider-line cell detection, 3:4 card cutting) and the pure framing geometry; the library never imports sharp — the app passes its own instance in
- **App owns policy** (`app/ai/ai-models.ts` overlay): free-tier bands and per-game caps (derived from the measured cost per bot turn in `app/ai/measured-turn-costs.json`, regenerated with `scripts/measure-turn-costs.ts`; sticker-price estimate until a model has 100 measured turns; **TEMPORARY since 2026-10-13: Gemini 4 Argon and Claude Sonnet 5.5 are forced to 1 bot per free game** by explicit `freeTier` lines above the banding loop, only to collect those 100 turns — remove each line once `measured-turn-costs.json` has them for that model), `DEPRECATED_MODEL_MAP`/`resolveModelId`, `RANDOM`, which image model each pipeline uses, story-generation settings, the avatar SUBJECT (who is on a sheet, how each character is described: `app/utils/avatar-generation.ts`) plus all avatar storage, candidates, drafts, reframing and billing, the voice metadata lists (`app/ai/voice-config/`: which voices exist per provider, gender, descriptions for casting); `app/ai/agent-factory.ts` wraps the library factory and wires `setLlmLogger` to BetterStack
- **Model updates** (new model, price change, reasoning pins) go in the LIBRARY repo's `src/catalog.ts`, then release: bump version, `git tag vX.Y.Z && git push origin main vX.Y.Z` (publishes via GitHub Actions), then `npm i @hiper2d/ai-agents@X.Y.Z` here. Never edit model facts in this repo — they don't live here anymore
- **Game language** (since 2026-10-28): the new-game form has a Language picker (`app/ai/game-language.ts`: 14 ISO codes, fixed list on purpose — a free-text field would be one more injection surface to screen). Model-written text gets a language block appended to the prompt (`languageInstruction(language, scope)`: casting + sheets in `preview-generation.ts`, the bot system prompt tail + the per-turn reminder in `bot-prompts.ts`, GM narration/summaries/suggestion) — English games get '' so their prompts and caches are byte-identical. Code-written lines (night header, "Day N begins", vote results, game-over, post-game, role names) live in `app/ai/game-text/en.ts` (`GAME_TEXT_EN`, `{placeholders}`) and render through `gameText(game, key, params)` from `app/ai/game-text`; for a non-English game the line comes from the STATIC locale `app/ai/game-text/locales/<code>.json` (since 2026-10-30 — before that a pinned Flash Lite model translated the set per game at preview time, which cost a call per game, varied per game, dropped the Chinese tally line and used the Japanese 人狼 in a Chinese game; the stored `gameText` on those games is read as a legacy fallback only). Each locale stores the `lineHash` of the English line it was translated from; `app/ai/game-text/locales.test.ts` fails on a missing, stale or placeholder-broken line, so adding or editing an English line means running `scripts/translate-game-text.ts` (Opus, ~$0.07 per language, translates only missing/stale keys; `--language`, `--force`, `--dry-run`) and reading the diff. Lines that need a role name are whole lines per role (`night_turn_<role>`, `eliminated_<role>`), never a name composed into a sentence (articles and plurals differ by language); languages without grammatical number translate `vote_line_one`/`vote_line_many` to the same text. Names are one-word identifiers in ANY script since 2026-10-28 (`app/utils/name-utils.ts`: `\p{L}\p{N}\p{M}`, NFC; a non-English cast is named in the game's script — the story block overrides the casting prompt's ASCII rule; both router judges accept non-ASCII question keys, probed 2026-10-28; name-keyed Firestore writes use `FieldPath` or whole-map rewrites, never dotted strings); `voiceStyle`/`visualDescription` stay English (speech/image prompts). The game's code is passed to speech-to-text as the hint. UI chrome stays English — not game content
- **One automatic re-send on empty or malformed answers** (since 2026-10-28, lib 0.30.0): every agent the app creates has `invalidResponseRetries = 1` (`app/ai/agent-factory.ts`), so a completion with no usable text, or JSON that fails the schema (`ModelInvalidResponseError`), is asked again ONCE before the error reaches the game. Timeouts, refusals, transport errors, output-cap hits (`truncated`) and semantically wrong answers (a dead target, a self-vote) are NOT retried — those stay user-driven, as before. The re-send runs the free-tier guard again. The library's retry hook writes an `llmRetry` notice on the game doc for the duration; the page polls `getLlmRetryNotice` (after 6 s, every 4 s, only while a game action is in flight — `app/games/[id]/llm-retry-notice.ts`) and the loading rail says "<name>'s model returned nothing, asking again" (never the name during NIGHT: hidden roles). Better Stack `activity = 'llm_retry'` warn lines count the re-sends; the error that finally surfaces carries `retries`

### Speaker routing (who talks next)
`app/api/bot-selection.ts` decides which bots reply after each message. With a Jev key configured (`TYPESAFE_API_KEY` in `config/freeTierApiKeys`; in `next dev` also `J_K`/`TYPESAFE_API_KEY` from `.env`) it runs the **Jev router** (`app/api/jev-router.ts` + `app/ai/jev-client.ts`; the question wording and score levels live in `app/ai/prompts/jev-router-prompts.ts`): one sub-second call to typesafe.ai's System One judge model returns an independent 0–3 reply `score` per bot (`reply_<name>`, four literal levels; the top level = "must reply now"), a `quiet_pick` choice over the quiet pool and an "is it dramatic" noul, and code composes the set (random 2–5 count, must-picks = top-level probability ≥ 0.6, fill by score, 1–2 slots from the quiet pool = the 3 least-active bots by `dayActivityCounter`, ordered by fewest messages then `quiet_pick` relevance, never the last author). Per-bot independent questions on purpose: a single `choice` over all bots is winner-take-all and starves the second and third speakers. Every call is recorded in full (state, questions, answers, decision, config) in the Firestore collection `jevRouterCalls` (`app/api/jev-records.ts`, 180-day `expireAt`); `scripts/jev-replay.ts --game <id> --last` re-runs the current selection logic on a recorded call. Better Stack (`activity = 'jev_router'`) and the dev console get only the decision, timing and cost — never the request or the raw answers (turned off 2026-09-19). Jev cannot generate text or count — keep those in code. Billed via `recordRouterSpend` (kind `router`). With both keys, Jev and OpenAI Decisions are asked AT ONCE (since 2026-10-09, to collect paired routing data for a later read of who picks better): Jev decides as soon as it answers and Decisions' answer is written onto the same `jevRouterCalls` row as `shadow` after the response (`after()`), including the speaker set its answers compose to with the SAME random draws, so a different `selected` is the judges' difference; both calls are billed. `quiet_pick` is optional: Decisions sometimes refuses it when no quiet bot fits the topic, and that drops only that answer (recorded as `refused`; the quiet slots fall back to fewest-messages order) instead of failing the call. A failed shadow judge logs at `warn`, a failed deciding judge at `error`. Without the Jev key, or when the Jev call itself fails (outage, 429, empty typesafe.ai prepaid balance), the same questions go to **OpenAI Decisions** (`app/ai/openai-decisions-client.ts`: `POST /v1/decisions` on `gpt-6-luna`, beta since 2026-10-06, $0.10/M input only, platform `OPENAI_API_KEY`; it translates Jev's noul/choice/score to predicate/choice/score and back, so the router runs on it unchanged via the `RouterJudge` param), — its call is already running, so the fallback adds no wait; the Jev error becomes the shadow — and only when both fail (`JevRouterUnavailableError`) does the Game Master LLM router run (warn logs `<judge> router unavailable, falling back to …`); other errors such as the free-tier cap still propagate. Measured 2026-10-07 on the day-2 fixture: same top and quiet picks as Jev, 210-620 ms vs Jev's 210-300 ms, `dramatic` reads lower (the 0.85 illustration threshold is tuned on Jev). typesafe.ai has no balance/usage API — the budget is guarded by auto reload in console.typesafe.ai/settings/billing.

### Content screen (human input)
`app/api/jev-screen.ts` judges every piece of text a HUMAN types — a chat message (in `handleHumanPlayerMessage`, before it is saved), a new game's name/theme/instructions/art style (in `previewGame`, before any story token), and since 2026-10-30 everything else too: the CAST as submitted to `createGame` (`screenCast`, source `cast`: opening story, voice directions, every bot's name/backstory/appearance in one call — all editable after the preview, found when a player whose art style was set aside pasted the same text onto all nine appearances), a vote reason (`vote`), a werewolf-chat message or night-action hint (`night`), a mid-game voice direction (`voice_style`); in enforce mode vote/night actions return `rejected` and the modal keeps the draft with the notice — with one ~200 ms Jev call: a 0–3 risk `score` over four literal levels plus five yes/no flags (sexual, minors, hate, real_harm, jailbreak); wording in `app/ai/prompts/jev-screen-prompts.ts` (bump `JEV_SCREEN_PROMPT_VERSION` on any edit). **Image question** (since 2026-10-13): where text reaches an image prompt (sources `preview`, `art_style`, `cast`) a sixth question asks whether an IMAGE model's filter would refuse the pictures — a separate criterion on purpose: Gemini's image endpoint refused "nude women" (HTTP 400) while the text side only read grey. Since 2026-10-30 the question names NUDITY AND SEX ONLY (naked, exposed breasts/buttocks/genitals, a sexual act, a sexualized child) and says No to everything clothed however emphasized: Gemini drew a cast of nine "in a bikini with a bubble butt … large boobs" six times without a complaint, and the 10-13 record re-read shows the "bikinis, big boobs, sexy" style got ONE 400 on a reroll while the same game drew two sheets and five illustrations with it — the image filter is a per-image coin, not a rule on wording, so body emphasis in clothes is not its line and the rule is to block only what providers block. Clothed styles now read 0.21/0.49 and pass on purpose — a rare 400 is a reroll away. At or above `IMAGE_REFUSAL_PROBABILITY` (0.6) the text is *set aside*, in monitor mode too (not a rejection): the preview comes back with an empty `artStyle` and an `artStyleNotice` the form shows under the field; `createGame` and `generateDraftIllustrations` re-screen the style via `screenArtStyle` (source `art_style`) because it is editable after the preview — creation drops it silently (warn log), the paid draft throws so the panel shows why; a `cast` past the bar has every bot's `visualDescription` dropped at creation (portraits then follow the backstories; warn log "Character appearances set aside"). Recorded as `imageRefusal` on the row; read it against the image refusals in the logs before moving the bar. The point is the platform keys: a provider that keeps receiving content it has labeled prohibited flags the account, and the per-game provider block list only stops the second hit. Verdicts: `ok`, `grey` (score ≥ 1.2, or top-two-level probability ≥ 0.6 with the strongest flag as reason; logged only), `would_block` (hard flags ONLY: minors/real_harm ≥ 0.9 — the score never blocks since 2026-10-08: 56 of 836 inputs were score-blocks over 30 days and providers refused none; `hate` dropped from the hard flags 2026-10-26: its whole record was five n-word messages in one game plus a self-deprecating "I'm legally retarded" bit, 0.90-0.98 on both judges, zero refusals — the rule is to block only what providers block, and hate stays a monitored grey reason). Mode is the `jevScreenMode` field of Firestore `config/limits`: `monitor` (default: record only, never rejects), `enforce` (would-block rejects — chat returns `GameActionResponse.rejected` and the composer keeps the draft with a notice; preview throws, the form shows the message), `off`. Bot output is never screened. Two judges are asked AT ONCE (since 2026-10-09): Jev (3 s) and OpenAI Decisions (3 s, same client as the router's backup). Jev decides; Decisions decides when Jev fails; the other judge's answer is stored on the same row as `shadow` (one row per input, both calls billed) to collect paired verdicts — `jev-screen-report.ts` prints them side by side. Only when both fail does the input go through unscreened (`error` row). Decisions scores ~0.5 lower than Jev (replay 2026-10-08, 63 rows), which is why only the hard flags block. Every call is recorded in full in the Firestore collection `jevScreenCalls` (`app/api/jev-records.ts`, 180-day `expireAt`, flat rows meant for a later BigQuery export); Better Stack (`activity = 'jev_screen'`) carries only the verdict, never the screened text or answers; billed as SpendKind `screen`. `scripts/jev-screen-report.ts --days 7 [--all] [--replay]` prints the verdict distribution, latency, the grey/would-block rows and a join against games that later hit a provider refusal — read that before switching to `enforce`. Marlow's daily Werewolf stats report (`~/projects/marlow/handlers/werewolf_stats.py`, 05:05 UTC, Telegram digest) reads the same collection and carries the day's would-block rows and the refusal join.

### Game State Management
- **Game States**: WELCOME → DAY_DISCUSSION → VOTE → VOTE_RESULTS → NIGHT_BEGINS → GAME_OVER
- **State Queues**: `gameStateParamQueue` and `gameStateProcessQueue` manage state transitions
- **Message System**: All game interactions are messages with types (GM_COMMAND, BOT_ANSWER, etc.)

### Authentication & Data
- **NextAuth v5**: GitHub and Google OAuth providers
- **Firebase**: Firestore for data persistence, Firebase Auth integration
- **Tiers & Billing**: Two tiers — free (capped: $5/UTC day and $20/month of platform-key AI spend across ALL paths, plus 5 games/day; live values in Firestore doc `config/limits` read by `app/api/limits-actions.ts`) and paid (prepaid USD balance via Stripe, 15% markup, no caps). All AI calls use platform keys (Firestore doc `config/freeTierApiKeys`); users never supply their own API keys. Every spend goes through `recordSpend` (`app/api/cost-tracking.ts`), which charges, updates `users.spendings` (monthly) + `users.dailySpend` and writes a `requestStats` row in one transaction; the free-tier guard `assertFreeSpendWithinLimit` runs before every LLM ask via the agent-factory `setBeforeAskHook` and explicitly before images/voice. Design: `docs/plan-user-spend-tracking-and-daily-cap.md`

### Key Directories
- `app/ai/`: prompts, model policy overlay (`ai-models.ts`), factory wrapper — agent implementations are in `@hiper2d/ai-agents`
- `app/api/`: Server actions for game/user operations  
- `app/games/[id]/`: Game UI and components
- `firebase/`: Firebase configuration and rules
- `scripts/`: Utility scripts for message/game operations

### Message Flow
1. Game Master sends commands to bots
2. Bots respond via AI agents using conversation history
3. All messages stored in Firestore with recipient targeting
4. SSE (Server-Sent Events) for real-time updates

## Production Debugging

To investigate user bug reports, stuck games, or production errors, use the `debugging` skill (`.claude/skills/debugging/SKILL.md`). It covers querying BetterStack app logs via the ClickHouse SQL API and reading production Firestore (find games by theme, dump game docs/messages/errorState) with the scripts in `werewolf-client/scripts/`. Credentials live in `werewolf-client/.env`.

## Usage Metrics

To answer "how many", "what do players choose", "does anyone use X" questions (languages, models, voices, cast edits, retention, spend by day or model), use the `metrics` skill (`.claude/skills/metrics/SKILL.md`). It maps each question to the collection and script that answers it (`featureEvents` `game_created` rows carry the form choices and the preview edits; Marlow's history file is the only series older than 30 days) and lists the caveats: retention windows, own-account exclusion, UTC.
