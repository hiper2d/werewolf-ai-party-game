## Root cause

`talkToAllImpl` (`app/api/bot-actions.ts:461`) re-reads the game after processing the bot queue:

```ts
const updatedGame = await getGame(gameId) as Game;   // returns null — cast masks it
if (!isAfterGameDiscussion && shouldTriggerAutoVote(updatedGame)) {  // reads .gameState → TypeError
```

The initial `getGame` at the top of the function is null-checked, but the mid-flight re-read is not. When the doc vanishes between the two reads (owner deletion), `shouldTriggerAutoVote(null)` throws at `bot-actions.ts:265`. The errorState persist then correctly fails because the doc is gone.

Firestore confirms the game no longer exists.

## Assessment

- **User impact: none.** The game was deleted by its own owner; the error hit the request that was already moot.
- **Not a provider/model issue** — all agent calls that night succeeded.
- This fits the stale-action no-op pattern: deleted-mid-action should log a STALE_ACTION warn, not an error + failed errorState persist.

## Optional hardening

1. In `talkToAllImpl` (and the similar re-read in `processNextBotInQueue`, `bot-actions.ts:415`), null-check the re-read game and return a stale no-op ("game was deleted mid-action") instead of casting `as Game`.
2. In `server-action-wrapper.ts`, when persisting errorState fails with "Game not found", downgrade both log lines to warn — the doc is gone, there is nothing to persist to.
